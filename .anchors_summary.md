### Key Design Decisions

- **DEC-2026-0030** Pipeline Orchestration Separation:
  - Pipeline is the ONLY module that orchestrates engines
  - Individual engines NEVER call other engines
  - Error containment: no exceptions between stages
  - Skip propagation: failed stage → subsequent stages SKIPPED

- **DEC-2026-0032** Pipeline Provenance:
  - Every stage records timing (`durationMs`), version, evidence IDs
  - Pipeline aggregates into a unified `PipelineProvenance` with `runId`, timestamps

- **DEC-2026-0033** Pipeline Stage Contract:
  - Every pipeline stage returns the SAME canonical `PipelineStageResult<T>`
  - `status`: SUCCESS | FAILED | SKIPPED
  - No stage-specific wrapper objects

- **DEC-2026-0034** Execution Success vs Governance Success:
  - A pipeline stage succeeds when it completes execution correctly
  - The business result may still indicate governance failure
  - Execution status SHALL NOT be inferred from validation outcome
