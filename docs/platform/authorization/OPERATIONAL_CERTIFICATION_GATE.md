# Operational Certification Gate

> **Purpose:** Before W4B (Dual Decision) can begin, the authorization system must pass operational certification. This gate ensures that the new engine has been validated against real production shadow data and meets all quality criteria.

---

## Gate Criteria

| # | Criterion | Requirement | Evidence | Method |
|---|-----------|:-----------:|----------|--------|
| O01 | **Match rate** | ≥ 99% | `PARITY_METRICS.json` | Automated |
| O02 | **Unexpected ALLOW** | 0 | `PARITY_METRICS.json` | Automated |
| O03 | **Critical mismatches** | 0 | `PARITY_MISMATCHES.json` | Automated |
| O04 | **High mismatches** | 0 | `PARITY_MISMATCHES.json` | Automated |
| O05 | **Resource coverage** | All DecisionOS resources covered | `PARITY_COVERAGE.json` | Automated |
| O06 | **Policy coverage** | All 7 active policies exercised | `PARITY_POLICY_ACCURACY.json` | Automated |
| O07 | **Latency budget** | Avg ≤ +5ms, P95 ≤ 10ms, P99 ≤ 20ms | `PARITY_LATENCY.json` | Automated |
| O08 | **Engine errors** | 0 | `PARITY_METRICS.json` | Automated |
| O09 | **Baseline snapshot** | `PARITY_BASELINE.json` exists | File check | Automated |
| O10 | **Replay dataset** | `DECISION_REPLAY.json` exists | File check | Manual |

## Operational Certification Checklist

```text
Before signing off on W4B, verify:

[  ] O01: Match rate >= 99%
[  ] O02: Unexpected ALLOW = 0
[  ] O03: Critical mismatches = 0
[  ] O04: High mismatches = 0
[  ] O05: All DecisionOS resources covered
[  ] O06: All 7 policies exercised
[  ] O07: Latency within budget
[  ] O08: Zero engine errors
[  ] O09: Baseline snapshot preserved
[  ] O10: Replay dataset preserved

Certification decision:
[  ] PASS — Proceed to W4B (Dual Decision)
[  ] FAIL — Address gaps before W4B
```

## Drift Detection After Certification

Once the baseline is established, every future commit must not degrade:

```bash
# Generate new report
generateParityReport(shadowLogger)

# Compare with baseline
detectDrift(baselineReport, currentReport)

# If drift detected:
#   severity = 'critical'  → Block commit
#   severity = 'major'    → Require review
#   severity = 'minor'    → Accept with note
```

## Synthetic Scenarios for Coverage Gaps

If operational traffic does not cover all required dimensions, synthetic scenarios must be executed. Each scenario targets a specific gap.

### Scenario Template

```typescript
import { AuthorizationEngine, Decision } from '@/lib/authorization/engine'

async function executeSyntheticScenario(engine: AuthorizationEngine) {
  const result = await engine.authorize({
    userId: 'synthetic-user',
    organizationId: 'synthetic-org',
    role: 'INTEGRATION_ACCOUNT',   // <-- target role
    resourceType: 'workbook',       // <-- target resource
    action: 'workbook.export',      // <-- target action
    context: { isBulkOperation: true },
  });
  console.log(`Synthetic scenario: ${result.decision}`);
}
```

### Required Synthetic Scenarios

| # | Targets | Scenario | Coverage Gap If Missing |
|---|---------|----------|------------------------|
| S01 | `EXTERNAL_AUDITOR`, read, mutation | Auditor reads evidence, auditor tries to upload | POL-05 not exercised for ALLOW + DENY |
| S02 | `INTEGRATION_ACCOUNT`, export | Integration account exports workbook | POL-04 REQUIRE_APPROVAL path |
| S03 | Any role, `project.delete` | User deletes a project | POL-07 REQUIRE_APPROVAL for A01 |
| S04 | `ANALYST`, `workbook.export` | Analyst exports workbook | POL-07 REQUIRE_APPROVAL for A02 |
| S05 | `ANALYST`, bulk operation | Analyst runs bulk import | POL-09 DENY path |
| S06 | `ORG_ADMIN`, `membership.assignRole` | Admin assigns role to user | POL-07 REQUIRE_APPROVAL for A08 |
| S07 | `BUSINESS_MANAGER`, `settings.update` | Manager updates settings | POL-04 DENY path + POL-07 |
| S08 | `READ_ONLY`, mutation | Read-only tries to delete | POL-05 not applicable — role has no permission |

Execute each missing scenario manually and verify the engine decision matches expectations.
