# v0.1 Release Readiness Pass — Proxy/Sentry/Jest Hardening

**Date:** 2026-05-31  
**Status:** Evidence report (implementation reality)

## What Changed

- Migrated the Next.js edge perimeter from deprecated `middleware.ts` convention to `proxy.ts` (Next.js 16 file convention) by replacing `src/middleware.ts` with `src/proxy.ts`.
- Updated Sentry client instrumentation per Next.js guidance:
  - Removed `sentry.client.config.ts`.
  - Added `src/instrumentation-client.ts` and exported `onRouterTransitionStart`.
  - Kept server/edge config through `src/instrumentation.ts` imports.
- Silenced Sentry build noise when no `SENTRY_AUTH_TOKEN` is provided by configuring `withSentryConfig` to run `silent` in that case.
- Eliminated Jest haste-map collisions caused by `.next/standalone/package.json` by ignoring `.next/` in `jest.config.js`.
- Reduced expected console noise in two tests (`sales-runtime-bridges.test.ts`, `sales-actions.test.ts`) by mocking `console.warn/error` within those specific tests.
- Updated docs and skills references from `src/middleware.ts` to `src/proxy.ts` where they describe current runtime behavior.

## Why

- Next.js 16 deprecates `middleware` file convention in favor of `proxy`.
- Sentry warns when `sentry.client.config.ts` is used under newer conventions; client instrumentation belongs in `instrumentation-client.ts`.
- Jest haste-map collisions can cause flaky test runs after a build generates `.next/standalone` artifacts.
- Release readiness requires minimizing misleading warnings and keeping docs aligned with validated code reality.
